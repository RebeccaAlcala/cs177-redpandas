# Workstream 4: AI Pipeline

**Owns:** `lib/ai/`, `scripts/`, `data/ai-cache/`
**Story map:** After-meeting summaries and action items covering conflicts and areas of confusion; AI annotates potential conflicts and what another team might mean by a term.

**Key idea:** the AI runs **offline as a script** and writes JSON files. The website only *reads* the JSON. This means the demo never fails because of an API outage, and nobody else needs an API key.

## Phase 1: Thu/Fri
- [ ] Get an Anthropic API key, put it in a local `.env` (never commit it)
- [ ] `scripts/generate-ai.ts`: for each meeting in `data/seed/meetings.json`, load its transcript, call Claude, write `data/ai-cache/<meetingId>.json` in the `MeetingSummary` shape from the contract
- [ ] Prompts in `lib/ai/prompts.ts`. Ask Claude (with JSON-only output) for:
  - [ ] **Summary points:** each one tied to the transcript segment ids it came from (these become `sourceIds` via segment → source mapping)
  - [ ] **Action items:** text + owner
  - [ ] **Confusions:** terms that different teams may use differently (e.g. "customer data"), with the segment where it came up
  - [ ] **Conflict candidates:** pairs of statements from different teams that contradict (output claim texts, team A/B, explanation, confidence, suggested follow-up questions)
  - [ ] **Unsourced claims:** statements of fact/number with no backing in the meeting or the provided Slack/docs
- [ ] Validate output with the contract types (use `zod` or a simple check); retry once on malformed JSON
- [ ] **Thursday evening:** run on seed meeting 1 and push the JSON so #2/#3/#5/#6 can integrate

## Phase 2: Fri/Sat
- [ ] Run on all seed meetings by Friday night
- [ ] Give the AI the seeded Slack threads and docs as context so it can detect "claim contradicts an existing doc" (e.g. the 5% vs 2% threshold)
- [ ] Output new Claims/Conflicts in the same ID conventions, or coordinate with #6 so the AI output and `data/seed/` claims/conflicts reference matching IDs. **Agree with #6 on one approach on Thursday:** simplest is that #6 hand-writes the canonical claims/decisions/conflicts, and #4's job is summaries, action items, and confusions that reference those claim IDs.
- [ ] Hand-review every output; fix by editing the JSON directly if the AI got something wrong (it's the demo, accuracy of the *story* matters)

## Phase 3: Sun
- [ ] Re-run if seed data changed; check no summary point has an invalid `claimId` or `sourceId`
- [ ] Short `lib/ai/README.md`: how to re-run the script

## Nice to have
- [ ] A "Regenerate summary" button wired to a real API route (clearly optional; cached output stays the default)

## Done when
- Every seed meeting has a cached summary JSON that passes validation
- Summaries read naturally and every point has at least one source id
- At least 2 meaningful conflicts/confusions are surfaced in the AI output for the demo
